# 系统错误与状态

> **来源**：提取自 `main` 分支（`contracts/error-codes.md`、`contracts/task.schema.json`、`docs/ADR/ADR-003`、`docs/ADR/ADR-004`）
> **状态**：讨论起点，未经六人确认。文末「待确认」是本阶段需要定下来的部分。

## 本文范围

第一阶段要确认的三类公共信息之一：**系统错误定义与状态**。

---

## 一、状态机

```
QUEUED ──► RUNNING ──┬──► SUCCEEDED     结果可用
                     ├──► FAILED        系统执行错误
                     ├──► TIMED_OUT     超时
                     └──► CANCELLED     被取消
```

| 状态 | 含义 |
| --- | --- |
| `QUEUED` | 已受理，尚未开始。创建接口立即返回此状态 |
| `RUNNING` | 后台执行中 |
| `SUCCEEDED` | 结果可用，`output` 必填 |
| `FAILED` / `TIMED_OUT` / `CANCELLED` | 终态，`error` 必填 |

终态一经到达不再变更。

---

## 二、三条交付约束

1. `output` 与 `error` **只在终态出现**；`QUEUED` / `RUNNING` 不得携带二者——否则消费方要同时处理两种输出形状。
2. `SUCCEEDED` 必填 `output`，且**不得**同时携带 `error`。
3. `FAILED` / `TIMED_OUT` / `CANCELLED` 必填 `error`。

---

## 三、核心语义：发现问题 ≠ 执行失败

| | 系统执行错误 | 正常分析发现 |
| --- | --- | --- |
| **含义** | 任务本身没跑完 | 任务正常跑完了，并且发现了问题 |
| **存放位置** | `error` | `output` / 报告产物 |
| **任务终态** | `FAILED` / `TIMED_OUT` / `CANCELLED` | **仍是 `SUCCEEDED`** |
| **举例** | 镜像构建失败、任务超时、分析器崩溃 | 检出缺失依赖、检出冗余依赖 |

这条线是跨服务交接最容易出错的地方。把"检出问题"写成失败，会让调度器把一次成功的分析当成基础设施故障去重试——而重试的代价可能是一次完整构建。

**三问自检**（接入前应确认双方答案一致）：

1. 检测服务报告了一条缺失依赖，这个任务的状态是什么？→ `SUCCEEDED`
2. 分析进程崩溃了？→ `FAILED`，错误码 `ANALYSIS_5001`
3. 修复服务把所有候选补丁都拒了？→ `SUCCEEDED`（"这批候选都不可接受"是正常工作的结论）

---

## 四、错误码

**编码形式**：`<阶段>_<四位数字>`，四位数字按类分段。

| 段 | 范围 | 用途 |
| --- | --- | --- |
| 3xxx | 环境 | 镜像、仓库拉取、工具链 |
| 4xxx | 执行 | 超时、取消、资源不足 |
| 5xxx | 分析 | 解析器、分析器内部故障 |
| 6xxx | 修复 | 修复输入、补丁生成与应用 |

**已定义的错误码**：

| 错误码 | 含义 |
| --- | --- |
| `ENV_3002` | 镜像构建失败 |
| `EXEC_4002` | 任务超时 |
| `ANALYSIS_5001` | 分析器失败（**不是**"检出问题"） |
| `REPAIR_6001` | 修复输入不可用：报告取不到 / 不符合契约 / 版本与请求不符 |
| `REPAIR_6002` | 修复过程无法进行：缺补丁工具、工作副本不可写 |

`error.stage` 的取值：`ENV` / `EXEC` / `ANALYSIS` / `REPAIR`

## 待确认

1. **受理阶段被拒绝的请求用什么错误码。** main 里同一个事实存在两种载体——受理阶段直接拒绝，或建任务后执行失败——而且实现与文档对用什么码的说法不一致。
2. **各错误码的生产者。** 哪些码允许检测侧产出、哪些只属修复侧，需要确认，避免两组各写一套。
3. **复检失败算哪一类。** 补丁应用后复检没通过，既不是"检出问题"，也不完全是"工具没跑完"，目前没有明确归属。
4. **状态取值是否够用。** 例如"部分成功"（修复采纳了部分候选、拒绝了部分）目前不体现在状态里。
