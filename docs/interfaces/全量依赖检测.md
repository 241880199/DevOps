# 全量依赖检测

- **端点**：`POST /v1/full-check-jobs`
- **`job_type`**：`FULL_CHECK`
- **状态**：提案，待双方确认后冻结

## 一、生产侧与消费侧

| 角色 | 谁 | 做什么 |
| --- | --- | --- |
| 生产侧 | 全量检测（BuildChecker） | 在环境里执行完整构建，比对实际依赖与声明依赖 |
| 消费侧 | 增量检测 | 取回基线实际图，作为下一轮增量推断的锚点 |
| 消费侧 | 依赖修复 | 取回错误报告，作为待修复问题的来源 |
| 消费侧 | 平台任务入口 | 按 `job_id` 查询任务结果 |

在本仓库的产出方矩阵里，**`ACTUAL_GRAPH` 与 `DECLARED_GRAPH` 只能由本接口产出**。

## 二、约定内容

### 1. 创建请求

```json
{
  "job_type": "FULL_CHECK",
  "trace_id": "trace-full-0001",
  "input": {
    "repository": {
      "url": "https://github.com/241880199/DevOps.git",
      "canonical_url": "https://github.com/241880199/DevOps",
      "commit": "d47a1523beec3311033eabf2e74c2a6ac299720d"
    },
    "environment_id": "env-draft-fixture-mode0",
    "limits": { "timeout_seconds": 3600 }
  }
}
```

| 字段 | 必填 | 语义边界 |
| --- | --- | --- |
| `repository.url` | 是 | 调用方原始仓库地址，原样保留 |
| `repository.canonical_url` | 是 | 按平台规则规范化的地址，用于地址比较与关联；缺失即拒绝 |
| `repository.commit` | 是 | **完整 40 位 SHA**，不接受缩写、分支名或标签 |
| `environment_id` | 是 | 平台全局环境 ID。镜像、项目根与构建命令**不内嵌于任务**，一律从环境读取 |
| `limits.timeout_seconds` | 否 | 单次检测的墙钟上限 |

环境必须存在且已声明 `ptrace`——检测要读文件访问记录；不满足时请求在受理阶段被拒。

### 2. 成功输出

| 字段 | 语义边界 |
| --- | --- |
| `resolved_commit` | 实际检测的完整 40 位 SHA，供下游确认「报告与基线是同一版本」 |
| `environment_id` | 本次检测所处的环境，回显以便下游对齐基线 |
| `actual_graph_artifact_id` | 实际依赖图（`ACTUAL_GRAPH`）的全局产物编号 |
| `declared_graph_artifact_id` | 声明依赖图（`DECLARED_GRAPH`）的全局产物编号 |
| `error_report_artifact_id` | 依赖问题报告（`ERROR_REPORT`）的全局产物编号 |
| `summary.missing` / `.redundant` | MD / RD 计数，供消费方在不解全部发现的情况下掌握规模 |

三份产物一律经 `GET /v1/artifacts/{artifact_id}` 取回（见 `下载产物.md`），取回后按记录的 `sha256` 核验。

### 3. 依赖图的结构

两张图同构，靠 `graph_kind` 区分。每张图都携带 `repository` 与 `environment_id`——**图必须绑定版本与环境**，否则两份图不可比。

| 部分 | 字段 |
| --- | --- |
| 图属性 | `schema_version`、`repository`、`environment_id`、`graph_kind`（`ACTUAL` / `DECLARED`）、`generated_at` |
| 节点 | `id`、`kind`（`TARGET` / `SOURCE` / `HEADER` / `GENERATED` / `OTHER`）、`path` |
| 边 | `target`、`dependency`、`relation`（`READS` / `DECLARES`）、`evidence` |

### 4. 错误边界

检出 MD / RD 时任务终态仍是 `SUCCEEDED`——检出问题是完成了工作，不是失败。分析器本身没跑完才用 `FAILED / ANALYSIS_5001`。

## 三、可执行的最小检查

| 用例 | 期望结果 |
| --- | --- |
| 有效全量检测请求 | `202` → `SUCCEEDED`，输出三个产物编号且都可下载 |
| `repository` 缺少 `canonical_url` | `400` |
| `commit` 非 40 位 | `400` |
| 缺少 `environment_id` | `400` |
| 引用未登记的环境 | `400` |
| 环境未声明 `ptrace` | `400` |
| 检出 MD / RD | `SUCCEEDED`，发现写入报告产物 |

## 四、双方确认状态

| 项 | 状态 |
| --- | --- |
| 依赖检测侧 | 已采用（见 `docs/ADR/ADR-008`、`ADR-010`） |
| 环境生成与依赖修复侧 | 待确认 |

待确认：`limits.timeout_seconds` 是否提升为四类任务的公共字段。
