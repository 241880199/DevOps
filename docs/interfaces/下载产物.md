# 下载产物

- **端点**：`GET /v1/artifacts/{artifact_id}`
- **适用**：四类任务共用
- **状态**：双方已确认并冻结

## 一、生产侧与消费侧

| 角色 | 谁 | 做什么 |
| --- | --- | --- |
| 生产侧 | 产出并保存产物的服务 | 各自保存自己产出的产物，登记产物记录 |
| 消费侧 | 所有下游服务 | 按 `artifact_id` 取回依赖图、错误报告、补丁、日志等内容 |
| 消费侧 | 维护者 | 复核产物内容 |

任务响应只承载元数据与小结果，大文件一律以「产物记录 + 引用」交接。理由见 `docs/ADR/ADR-002`。

## 二、约定内容

### 1. 产物记录

| 字段 | 必填 | 语义边界 |
| --- | --- | --- |
| `artifact_id` | 是 | 全局唯一，是**唯一的取回依据** |
| `type` | 是 | 八类之一：`DOCKERFILE` / `BUILD_LOG` / `VERIFY_LOG` / `IMAGE_REF` / `ACTUAL_GRAPH` / `DECLARED_GRAPH` / `ERROR_REPORT` / `PATCH` |
| `uri` | 是 | **给人的原始地址**，形如 `artifact://<存储域>/<job_id>/<文件名>`。它不是寻址依据 |
| `media_type` | 是 | 内容格式，下载响应的 `Content-Type` 取自它 |
| `producer_job_id` | 是 | 产出该产物的任务，用于追溯 |
| `environment_id` | 是 | 产物所属环境。环境生成服务自己的产物为 `null`——产出时环境尚不存在；其余产物必须记录所属环境 |
| `sha256` | 是 | 对**产物内容**计算，不是镜像 digest。取回后据此核验 |
| `size_bytes` | 是 | 内容字节数，不适用时为 `null` |
| `created_at` | 是 | 成功持久化并可引用的时间 |
| `source_commit` | 是 | 产物所针对的代码版本，八类一律必填 |

### 2. 存储域

域名按**服务**命名，取值集合是契约的一部分，由校验钉死：

```
draft  mdfixer  buildchecker  echecker  oracle
```

**人工基线样例**的产物用 `oracle` 域，以免冒充工具产出。新增域名必须先写进共享结构与文档，否则下游按域映射本地目录的约定会静默失效。

### 3. 定位机制

产物**分散存放**：各服务各自保存自己产出的产物。逻辑上采用**全局 Artifact Index** 的思路——`artifact_id` 在全平台唯一，并可据此定位存放位置；**实现上不要求部署一个独立的 Index 服务**，按存储域转发、各服务自维护目录、或一个中心服务，都属实现选择。

### 4. 核验与失败

取回后按记录的 `sha256` 与 `size_bytes` 核验内容完整。核验不通过说明存储或传输出了问题，不是内容本身有误。

`artifact_id` 未登记时返回 `404`，码为 `REQ_1002`（资源不存在）。

## 三、可执行的最小检查

| 用例 | 期望结果 |
| --- | --- |
| 按 `artifact_id` 取回 Dockerfile / 补丁 / 报告 | `200`，`Content-Type` 等于记录的 `media_type` |
| 核验取回内容与记录的 `sha256`、`size_bytes` | 一致 |
| 查询不存在的 `artifact_id` | `404` |
| 校验脚本核对样例记录的摘要与仓库里的真实文件 | 逐字节一致 |
| 存储域不在白名单内 | 契约校验失败 |
| 检测与修复的产物记录 `environment_id` 非 `null` | 通过；环境生成服务的产物记录为 `null` |

## 四、双方确认状态

| 项 | 状态 |
| --- | --- |
| 引用方式与核验 | 已采用（见 `docs/ADR/ADR-002`） |
| 存储域白名单 | 已采用并进入校验 |

**双方确认**：

- `size_bytes` 与 `created_at` 均为**必填**——十个字段在产物记录中始终存在，`size_bytes` 不适用的取 `null`，与 `artifact.schema.json` 的 `required` 一致；
- 「产物不存在」用 **`REQ_1002`**。
