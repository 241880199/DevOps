# E8 决策：验证间接包含往返，不扩大核心算法范围

## E10 决策

新增编译宏激活条件 include 的场景，使配置变化真正改变依赖集合。五次均从固定历史图分析，保存增量/全量原始结果，保留慢于全量的数据；不扩大核心算法范围。标准矩阵使用课程一键入口，记录其未保存每次 JSON 的证据限制。

背景：已有测试覆盖 main.c 的直接 include 新增，没有覆盖仅头文件变化后新增、稳定复用、移除的完整往返。

选择：保留教学 scan 的全局保守失效规则，新增独立测试与持久化验证入口。以完整实际图、声明图和发现作为对照，同时用真实 BuildChecker 交叉核对。

替代方案：改为按目标失效可减少刷新，但需要额外依赖传播与边界分析，本次 E8 不做该优化。复制已有直接包含测试覆盖不足，因此拒绝仅改文件名的重复测试。

代价与范围：包含变化后 helper.o 也刷新，性能不最优，但遵守当前教学契约。测试单独放置，课程 test_profile.py 仅增加导入，降低与组员修改冲突。

验证：8 项服务测试通过；标准 E8 和扩展 verification.json 均通过；扩展三轮动态交叉核验通过。精确路径与源码身份见个人报告。
# E9 决策补充（2026-11-07）

选择保留课程的保守全目标刷新，并增加多层头文件切换测试。预先创建两个叶子头文件，确保失效来自已有头文件的预处理指令变化，而非文件集合变化。先验证旧 MD 消除、新 MD 出现，再补声明验证实际图复用。使用独立预期和全量扫描比较，代价是未实现目标级最小刷新。普通代码修改前等待 1.05 秒，避免 Make 时间戳粒度使构建证据不可靠。
