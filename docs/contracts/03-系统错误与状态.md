# 系统错误与状态

> **来源**：六人共同讨论确定

## 本文范围

第一阶段要确认的三类公共信息之一：**系统错误定义与状态**。

---

## 一、状态机

```
QUEUED ──► RUNNING ──► 任意终态
   │
   └───────────────► CANCELLED

终态：SUCCEEDED / FAILED / TIMED_OUT / CANCELLED
```

| 状态 | 含义 |
| --- | --- |
| `QUEUED` | 已受理，尚未开始。创建接口立即返回此状态 |
| `RUNNING` | 后台执行中 |
| `SUCCEEDED` | 结果可用 |
| `FAILED` | 系统执行错误 |
| `TIMED_OUT` | 超时 |
| `CANCELLED` | 调用方取消 |

- 状态取值穷举，未知取值被拒绝；
- 终态一经到达不再变更；
- 取消由调用方发起，取消后仍可查询；
- 状态取值属于契约，删除、改名或改变语义都是破坏性变更。

**不设"部分成功"。** 部分成功的语义由 `output` 承载——例如修复的 `fixed` 与 `rejected`、检测的 findings——不通过新增状态取值表达。

---

## 二、交付约束

1. `output` 与 `error` 只在终态出现，`QUEUED` / `RUNNING` 不出现；
2. `SUCCEEDED` ⟹ 必有 `output`，且不得同时有 `error`；
3. `FAILED` / `TIMED_OUT` / `CANCELLED` ⟹ 必有 `error`。

---

## 三、执行错误与正常发现的分界

| | 系统执行错误 | 正常分析发现 |
| --- | --- | --- |
| **含义** | 任务本身没跑完 | 任务正常跑完，并且发现了问题 |
| **存放位置** | `error` | `output` 或报告产物 |
| **任务终态** | `FAILED` / `TIMED_OUT` / `CANCELLED` | `SUCCEEDED` |
| **举例** | 镜像构建失败、任务超时、分析器崩溃 | 检出缺失依赖、检出冗余依赖 |

检出问题**不等于**执行失败。

**修复的候选全部被拒绝属于正常分析发现**：终态为 `SUCCEEDED`，`output.fixed` 为空、`output.rejected` 非空。

---

## 四、错误码

**编码形式**：`<阶段>_<四位数字>`。

| 段 | 范围 | 归属任务 |
| --- | --- | --- |
| 1xxx | 请求 | 统一任务入口在受理阶段产出的请求与引用问题 |
| 3xxx | 环境 | 任何需要环境的任务 |
| 4xxx | 执行 | 任何任务（超时、取消、资源不足、产出违约） |
| 5xxx | 分析 | 检测类任务（`FULL_CHECK`、`INCREMENTAL_CHECK`） |
| 6xxx | 修复 | `REPAIR` |

错误码按**阶段**归属，不按服务归属——阶段是任务拥有的属性。

**已定义的错误码**

| 错误码 | 含义 |
| --- | --- |
| `REQ_1001` | 请求不合法 / 输入不可用：字段校验失败、必填缺失、路径越界、引用未登记的环境或产物。以 HTTP `400` 承载 |
| `REQ_1002` | 资源不存在：任务、环境或产物未登记。以 HTTP `404` 承载 |
| `ENV_3002` | 镜像构建失败 |
| `EXEC_4002` | 任务超时 |
| `EXEC_4003` | 契约自检失败：服务产出不符合契约。不可重试 |
| `ANALYSIS_5001` | 分析器失败（**不是**"检出问题"） |
| `REPAIR_6001` | 修复输入不可用：报告取不到、不符合契约，或版本与请求不符 |
| `REPAIR_6002` | 修复过程无法进行：缺补丁工具、工作副本不可写 |

`error.stage` 的取值：`ENV` / `EXEC` / `ANALYSIS` / `REPAIR`。

新增错误码时，同步更新本文与任务模型的 `error.code` 约束。

---

## 五、受理阶段的拒绝

任务错误码只用于**任务终态**。创建请求在受理阶段被拒绝时任务尚未存在，因此由 **HTTP 4xx 加错误响应体**表达，**不写入 `error`**。

同一类问题若既可能在受理阶段被发现、也可能在执行阶段被发现（例如报告版本与请求不符），两侧使用**同一个错误码**，便于调用方统一处理；区别只在载体——一个是 HTTP 响应体，一个是任务的 `error`。

## 六、本文件的边界

状态机与错误码同时出现在三份文件里，各自的职责是：

| 文件 | 职责 |
| --- | --- |
| **本文** | **定义层**：状态机、分段规则、错误与发现的分界。有争议时以本文为准 |
| `contracts/error-codes.md` | **归档层**：已定义码表、生产者、样例索引，由 `scripts/validate.py` 比对 |
| `docs/interfaces/查询任务.md` | **接口层**：面向消费方的返回体与交付约束，内容不得与本文冲突 |

**三处的码表与状态取值必须同步。** 改任何一处都要同时改另外两处与 `contracts/task.schema.json` 的枚举。
