# 公共数据结构

> **来源**：六人共同讨论确定
> **阅读方式**：每节先给总览，再给详细边界

## 本文范围

第一阶段要确认的三类公共信息之一：**各接口共用的数据结构**。

| 结构 | 回答的问题 |
| --- | --- |
| 任务（Job） | 做什么动作 |
| 产物引用（Artifact） | 产出了什么 |
| 仓库与版本标识（Repository） | 执行什么代码 |
| 环境标识（Environment） | 在哪里、以什么方式执行 |

本文只列各接口共用的部分；各接口自己的字段属于第二阶段。

---

## 一、任务（Job）

### 快速总览

四类任务共用同一套外层结构。

| 组 | 字段 | 边界 |
| --- | --- | --- |
| **Identity** | `schema_version`、`job_id`、`trace_id` | 回答"这是什么、属于哪次流程"；创建后不可变 |
| **Lifecycle** | `status`、`job_type` | 回答"任务进行到哪一步"；不表达结果好坏 |
| **Execution** | `created_at`、`started_at`、`finished_at`、`attempt` | 任务级的时间与尝试次数，以服务端时钟为准 |
| **input** | 由 `job_type` 决定 | 调用方提交并经服务接受的输入快照，创建后不可变 |
| **result** | `output`、`error` | 终态结果，成功产出与失败原因互斥 |

### 1. Identity

**边界**：身份回答"这是什么、属于哪次流程"，不回答任务的进展与结果。三项在 Job 创建后均不可变。

| 字段 | 必填 | 语义边界 |
| --- | --- | --- |
| `schema_version` | 是 | Job Schema 的契约版本，声明读这份数据要按哪一版规则解析。**覆盖公共外壳与四类任务各自的 `input` / `output` 形状**，任何一处形状变化都递增。不是任何具体服务的实现版本。 |
| `job_id` | 是 | **一次任务实例**的编号，**平台级全局唯一**。由服务端产生，创建请求中不得携带；重试与新一轮都不复用。 |
| `trace_id` | 否 | **一次业务流程的串联号，覆盖多轮反馈循环**。跨多个 `job_id` 的唯一串联键。不承载业务含义、不参与判定。由调用方透传，缺失时服务端生成。 |

### 2. Lifecycle

**边界**：生命周期回答"任务进行到哪一步"，不回答"结果好不好"。检出问题仍然是成功完成。

| 字段 | 必填 | 语义边界 |
| --- | --- | --- |
| `status` | 是 | 任务自身的执行状态。取值穷举，未知取值被拒绝。只能由拥有该任务的服务修改。 |
| `job_type` | 是 | 任务种类，决定 `input` 与 `output` 的结构。创建后不可变，必须与创建端点一致。 |

```
QUEUED ──► RUNNING ──► 任意终态
   │
   └───────────────► CANCELLED

终态：SUCCEEDED / FAILED / TIMED_OUT / CANCELLED
```

- `QUEUED` 只能到 `RUNNING` 或 `CANCELLED`；
- `RUNNING` 可以到任意终态；
- 终态不可再次转换；
- 取消由调用方发起，取消后仍可查询。

### 3. Execution

**边界**：三个时间字段描述**任务级**的时间，不描述单次尝试的时间。全部以服务端时钟为准，不接受调用方提供。三个字段始终存在，尚未发生的取 `null`。

| 字段 | 必填 | 语义边界 |
| --- | --- | --- |
| `created_at` | 是 | 服务**成功创建 Job 资源并持久化之后**的服务端时间。 |
| `started_at` | 否 | 该 Job **第一次**开始执行的时间。不随重试更新。 |
| `finished_at` | 否 | 该 Job **最终进入终态**时的服务端时间。 |
| `attempt` | 是 | 最终完成前**实际执行的尝试次数**。尚未开始执行时为 `0`；首次进入执行时变为 `1`，每次重新执行递增 1。 |

时间格式：RFC 3339 / ISO 8601，UTC，毫秒精度。

`attempt` 的边界：

- 只计**同一个 `job_id` 上被重新执行**；
- 任务内部的迭代不计入，由 `input` 里的轮数上限约束；
- 重试时状态保持 `RUNNING`，不回 `QUEUED`；
- 不表达成功与否。

**不变式**

| 不变式 |
| --- |
| `created_at ≤ started_at ≤ finished_at`（三者非 null 时） |
| `status = QUEUED` ⟹ `started_at`、`finished_at` 为 `null`，且 `attempt = 0` |
| `status = RUNNING` ⟹ `started_at` 非 null 且 `finished_at` 为 `null` |
| `status` 为终态 ⟺ `finished_at` 非 null |
| `started_at` 非 null ⟺ `attempt ≥ 1` |
| 终态且 `started_at` 为 `null` ⟹ `status = CANCELLED` |

### 4. input

任务**输入快照**：调用方创建 Job 时提交、并经服务接受的输入参数。Job 创建后不可修改，不因重试、内部迭代或执行过程发生变化。具体字段结构由 `job_type` 对应的接口契约定义。

### 5. result

终态结果的统称，由两个并列字段承载。

| 字段 | 语义边界 |
| --- | --- |
| `output` | 成功产出。可以包含"发现了问题"。 |
| `error` | 系统执行错误。只写"判断没做成"类的故障，不写业务发现。 |

- 两者只在终态出现；
- `SUCCEEDED` ⟹ 必有 `output`，且不得同时有 `error`；
- `FAILED` / `TIMED_OUT` / `CANCELLED` ⟹ 必有 `error`；
- 不装大对象内容，大对象走产物引用。

**实际生效值与 `input` 的关系**：服务可能对输入做默认填充、规范化或约束调整。实际生效值**不得覆盖 `input`**；若该变化对任务执行语义或结果解释有重要影响，由具体接口契约定义 `effective_config` 或等价字段。

## 二、产物引用（Artifact）

### 快速总览

大文件不进任务响应，以"记录 + 地址"交接。

| 组 | 字段 | 边界 |
| --- | --- | --- |
| **身份** | `artifact_id` | 平台内唯一的产物编号 |
| **类型** | `type` | 八类之一 |
| **地址** | `uri`、`media_type` | 到哪里取、取回来是什么格式 |
| **来源** | `producer_job_id` | 哪个任务产出的 |
| **所属环境** | `environment_id` | 在哪个环境里产出的 |
| **校验** | `sha256`、`size_bytes` | 内容是否完整 |
| **追溯** | `created_at`、`source_commit` | 何时可被引用、针对哪个代码版本 |

产物类型共八类：`DOCKERFILE`、`BUILD_LOG`、`VERIFY_LOG`、`IMAGE_REF`、`ACTUAL_GRAPH`、`DECLARED_GRAPH`、`ERROR_REPORT`、`PATCH`

### 详细边界

| 字段 | 必填 | 语义边界 |
| --- | --- | --- |
| `artifact_id` | 是 | 全局唯一 Artifact 身份。 |
| `type` | 是 | 业务类型，八类之一。 |
| `uri` | 是 | **稳定逻辑 URI**，形如 `artifact://<存储域>/<job_id>/<文件名>`。逻辑地址，不表示物理位置——落到实际位置由取用方式负责。**存储域按服务命名，取值是白名单**：`draft` / `mdfixer` / `buildchecker` / `echecker`；人工基线样例用 `oracle`，以免冒充工具产出。 |
| `media_type` | 是 | 内容／表示格式。 |
| `producer_job_id` | 是 | **唯一**的具体产出 Job。 |
| `environment_id` | 是 | 该产物所属的环境。**DRAFT 产出的产物不适用**——它们产出时环境尚不存在。 |
| `created_at` | 是 | Artifact **成功持久化并可引用**的时间。 |
| `sha256` | 是 | 对 **Artifact 的实际内容**计算 SHA-256。**不是镜像 digest**。 |
| `size_bytes` | 是 | 内容字节数，不适用时取 `null`。 |
| `source_commit` | 是 | 产物所针对的代码版本，**八类一律必填**。 |

十个字段在产物记录中**始终存在**；不适用的取 `null`，不是省略字段。

**类型与产出方**

| `type` | DRAFT | BuildChecker | EChecker | MDFixer | 说明 |
| --- | :---: | :---: | :---: | :---: | --- |
| `DOCKERFILE` | 是 | — | — | — | 环境构建定义 |
| `BUILD_LOG` | 是 | 是 | 按实际执行 | 按实际执行 | 构建／执行日志 |
| `VERIFY_LOG` | 是 | 是 | — | 是 | 实际执行验证时产出 |
| `IMAGE_REF` | 是 | — | — | — | 镜像引用，被环境引用 |
| `ACTUAL_GRAPH` | — | 是 | — | — | 全量实际依赖图 |
| `DECLARED_GRAPH` | — | 是 | — | — | 全量声明依赖图 |
| `ERROR_REPORT` | — | 是 | 是 | — | 全量／增量检测均可产出 |
| `PATCH` | — | — | — | 是 | 修复产物 |

- "按实际执行"表示不是必须产出：该服务执行了对应操作并形成持久化日志时可以产出；
- 产出方不在允许列表内的产出被拒绝；
- 每条记录只有一个 `producer_job_id`。

### 存放与取用

- 产物**分散存放**：各服务各自存放自己产出的产物；
- 存储域**按服务命名**，取值受白名单约束（见上表 `uri` 行）；新增域名必须先写进共享结构与文档，否则下游按域映射本地目录的约定会静默失效；
- 取用一律走**下载接口** `GET /v1/artifacts/{artifact_id}`；
- 定位逻辑上采用**全局 Artifact Index**：`artifact_id` 全平台唯一，并据此定位存放位置。实现上不要求独立部署 Index 服务。

验证结论与验证日志的分工：结构化验证结论留在 `output`，详细执行日志放 `VERIFY_LOG`。

### 双方确认状态

| 侧 | 状态 |
| --- | --- |
| 环境生成与依赖修复侧 | 已确认 |
| 依赖检测侧 | 待确认 |

冻结后若要求改字段，按冻结结果**新开实现分支**同步，而不是只改文档。

## 三、仓库与版本标识（Repository）

### 快速总览

| 字段 | 边界 |
| --- | --- |
| `url` | 调用方给出的仓库地址，原样保存 |
| `canonical_url` | 按平台统一规则生成的规范地址，用于地址的比较与关联 |
| `commit` | 版本标识，完整 SHA |

### 详细边界

| 字段 | 必填 | 语义边界 |
| --- | --- | --- |
| `url` | 是 | 调用方提供的原始 Git 仓库地址，保留原始形式。 |
| `canonical_url` | 是 | 按平台统一规则生成的规范地址，用于地址的比较与关联。 |
| `commit` | 是 | **完整 40 位 SHA**。不接受缩写、分支名、标签。 |

- `canonical_url` **不是仓库的唯一身份**：它只解决"同一个地址的不同写法"，不保证识别不同 URL 是否实际指向同一个 Git 仓库；
- 只支持 git；
- 项目根路径不属于本节，归环境标识；
- 不表达工作副本状态；
- 只接受完整 SHA，因此本结构不需要 `effective_config`。

### 归一化规则

| 项目 | 规则 |
| --- | --- |
| 协议 | 只接受 `https://` |
| 主机名大小写 | 转小写 |
| 路径大小写 | 不转换 |
| `.git` 后缀 | 去除 |
| 末尾 `/` | 去除 |
| 默认端口 | 去除 `:443` |
| fragment、query | 禁止 |
| 用户名与密码 | 禁止 |
| host 别名 | 不自动推断 |
| 路径中的重复 `/` | 不压缩 |

hostname 转小写，path 保持原样。

归一化**只有一处实现**：一处产出结果、其余服务消费，或四个服务共用同一份实现。

## 四、环境标识（Environment）

### 快速总览

环境是**独立的业务对象**，不是产物。它回答"在哪里、以什么方式执行"，由一条镜像引用加一组运行约定组成。

仓库与环境**正交**：仓库回答"执行什么代码"，环境回答"在哪里、以什么方式执行"。

### 详细边界

| 字段 | 必填 | 语义边界 |
| --- | --- | --- |
| `environment_id` | 是 | 环境的身份，**平台全局唯一**，与 `job_id`、`artifact_id` 同一层级。 |
| `image` | 是 | 引用一条 `IMAGE_REF` 产物（按 `artifact_id` 引用），不内嵌镜像信息。 |
| `project_root` | 是 | 代码在容器内的位置。 |
| `working_directory` | 是 | 从哪个目录执行。 |
| `build_command` | 是 | 该环境约定的构建方式。 |
| `runtime_capabilities` | 是 | **执行该环境所需的运行能力**（v1 只有 `ptrace`）。是需求，不是"当前机器有什么能力"。 |

### 与其他结构的关系

- 环境**不内嵌仓库身份**，由 Job 同时引用仓库与环境；
- 环境在任务里**以 `environment_id` 引用**，不内嵌完整定义；
- 构建命令**只在环境里表达**，任务输入不重复传；v1 不支持按任务覆盖构建命令；
- 环境**创建后不可变**：需要改动时新建一个（`env-001` → `env-002`）；
- 原 `configuration_id` 由 `environment_id` 取代，不再单独存在。

### 引用方式

下游任务通过 `environment_id` 引用环境，完整定义由 Environment Provider（当前是 DRAFT）保存并提供。
