## 前置条件和执行

在 Linux 或 WSL Ubuntu 中执行，需 Git、GNU Make、C 编译器、Python 3、strace。
仓库的 `.gitattributes` 固定这些样例和脚本为 LF。确认本地 Git 身份已设置为本人学号。

```sh
git config --local user.name 241880444
git config --local user.email 241880444@smail.nju.edu.cn
git rev-parse HEAD
git status --short
python3 scripts/run_e3.py --student-id 241880444
# 使用上一步打印的 EVIDENCE_DIR，不要自行猜测哪个目录是成功记录
python3 scripts/verify_e3.py work/e3/<本次目录>
```

运行器每次创建新目录，只改副本，不清理已有工作。完整实验包含：

| 场景 | 预期 | 留证 |
| --- | --- | --- |
| MD/RD 初始构建 | 输出 1 | make 和 app 原始输出、退出码 |
| config.h VALUE 改成 2 | 增量输出 1，main.o 未更新；clean 输出 2 | 修改步骤、日志、mtime 断言 |
| unused.h 只改注释 | main.o 重新编译，输出仍为 2 | 编译日志、mtime 断言 |
| Linux 跟踪 | 实际打开 config.h | strace -ff 原始文件、make -pn 输出 |
| C0 | 正确声明，clean 输出 10 | 独立样例仓库真实提交和标签 |
| C1 | 新增 feature.h 使用但未声明，clean 输出 12 | 与 C0 的差异及人工 MD 预期 |
| C1 修改 feature.h | 增量仍为 12，clean 为 13；恢复后为 12 | 验证该 MD 的行为证据 |
| C2 | 只改编译命令为 -DMODE=7；增量 12，clean 19 | 保留 C1 产物、命令快照、与 C1 的差异 |

`fixtures/md-rd/oracle.json` 和 `fixtures/commits/oracle.json` 是人工预期，来源 MANUAL。
`summary.json` 是真实执行观察，来源 EXECUTION。现有 E2 的空图和空发现报告不会被
替换或计入此次检测效果。C2 的命令变化和缺失 feature.h 是分别记录的事实。

## 证据及移交

每次运行在 work/e3 下保存 environment.json、commands.json、summary.json、commits.json、
logs、原始 trace 和 fixture-history.bundle。命令包含实际 cwd、输出文件及退出码。
manifest.json 校验可移交证据的摘要；verify_e3.py 还会克隆 bundle，核验真实标签、
连续父子关系、源码摘要以及 C1/C2 的改动范围。失败时仍保存已有日志，并标记 FAILED。

fixture-repo 是本次样例仓库，三个完整 SHA 属于它，不是共享 DevOps 主仓库的版本。
要重用同一组 SHA，可克隆该次 fixture-history.bundle；每次重新生成的提交时间不同，
SHA 可以变化。移交时保存 bundle、commits.json 和对应日志，不用虚构 SHA。

精选证据归档到 evidence/e3/241880444/，保持路径和摘要一致；不要提交整份 work、
临时 .git 或构建产物。个人贡献在 docs/records/A03-BuildChecker.md 中记录。
