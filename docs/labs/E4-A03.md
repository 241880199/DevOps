# A03 E4 BuildChecker 可重复环境

依据：E4_可重复工程环境_20260929.pptx、A 组全流程手册及 E4 实验包 A-buildchecker。
唯一仓库继续承载 E2 共享契约。A 模板以新增 services、Compose、Makefile、锁文件等方式
接入；contracts、mock 和旧样例仍保持各自语义。

## 每名组员执行

在课程 Linux 服务器的个人学号目录，从本组真实远程仓库克隆。组员已克隆时先确认
origin 和工作区，再选择与他人对照的同一源码 SHA。命令手册使用的是服务器终端。

```sh
mkdir -p ~/241880444
cd ~/241880444
git clone https://github.com/241880199/DevOps.git devops
cd devops
# 如代码仍在功能分支，先检出组长给出的 feature/a03-e3-e4 或对应完整 SHA。
git config --local user.name 241880444
git config --local user.email 241880444@smail.nju.edu.cn
git remote -v
git rev-parse HEAD
git status --short
make all
```

没有 sudo 或管理员权限的组员无需安装第二套 Docker；缺失时由有权限者按课程手册
初始化。E4 A 组不需要真实 API Key。`.env` 自动生成并设置为 600，默认空值即可。

| 步骤 | 同一 work/<本次时间>/ 中的证据 | 判据 |
| --- | --- | --- |
| doctor | env.json | problems 为空；Git 学号和完整 source_sha 正确；正式留证源码无未提交改动 |
| build | build.log、image.json、toolchain.lock | 成功构建，记录 base digest、镜像 ID、源码 SHA、工具实际版本 |
| test | test.log | 5 passed：原模板 3 个，加程序输出和退出码两个拒绝用例 |
| smoke | smoke.json | make_exit_code=0、app_exit_code=0、app_output="1"、config_h_opened 非空、passed=true |
| scan | secret-scan.txt | 未发现问题，.env 未被跟踪且权限正确 |

Makefile 禁止并行运行任务，保证 make all 按顺序进行并落到同一目录。每次运行以
纳秒时间创建独立目录。基础 Python 镜像按课程 digest 固定，Python 包使用哈希锁。
系统工具导出实际版本；升级后须解释 toolchain.lock 的差异，不能只比较镜像 ID。

Compose：无网络、2 CPU、1 GiB 内存、256 PID、SYS_PTRACE、no-new-privileges。
服务 Dockerfile 使用 app 普通用户，只复制 A 组 md-rd 样例。E2 mock 不包含在服务镜像中。

## 验证扫描器和组员对照

按 A 组手册在自己的克隆里临时添加假 Key 文件并暂存，运行 make scan 应失败；
从暂存区和工作区移除后复扫应通过。假文件不得提交。扫描器在 Git 仓库中只检查已跟踪
或暂存的文件，因此未暂存的假文件无法验证检出。两次扫描产生自己的目录，不能替代
完整 make all 的成功证据。不要删除他人的 Docker 资源。

其他组员自行克隆同一 SHA、设置自己的学号并执行 make all。比较 toolchain.lock、
test.log 与 smoke.json 的结论；镜像 ID、耗时、PID 和 trace 行数可以不同。
当前用户只负责自己的记录，第二名组员未完成时明确写“待对照”，不模拟他人的完成状态。
E4 不要求个人提交；本次接入模板属于小组仓库的代码准备，区别于个人实验运行。

## 本地预验与后续

WSL Ubuntu + Docker Desktop 可以先验证代码和操作链路，但必须在记录中标明环境。
本地通过不能表述成 A03 阿里云服务器已验收。Docker Desktop 的 WSL 集成启用后可直接
使用 make all；若未启用，应按本地环境记录操作，勿修改共享服务器配置来迁就本机。

本次本地预验在 WSL 的 Linux 文件系统中完成。直接在 /mnt/e 的 Windows 挂载目录
运行会使 chmod 600 仍表现为 777，导致 .env 权限检查失败。正式本地验证应克隆到
Linux 目录。为不更改 Docker Desktop 全局设置，本次以 WSL root 使用 Desktop
原生 CLI 和 Unix 代理套接字，在个人目录配置 Compose/buildx 插件。临时 /tmp 配置
曾在后续启动时丢失，已改为个人目录的持久配置；失败自检和成功运行分别留证。

make shell 可进入服务容器并保留 /app/work 中的文件。E4 smoke 只保存少量跟踪摘要；
E5 需在同一镜像重新保存完整 strace -ff 和 make -p 输出。当前 CLI 只有 version/smoke，
后续 full-check、依赖构图和检测算法另按实验要求实现。
